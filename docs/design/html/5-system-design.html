SiteLog — System design

Every shared UI part, with its types, sizes, variants and states, measured on both platforms. Each part lists what it is for, its name in code (DS… in the iOS DesignSystem package and the Android :designsystem module), a spec table (sizes in pt on iOS, dp on Android; type, colour and spacing names from page 1), and one row per variant with iOS 26 and Android side by side. Variants follow one rule so each maps 1:1 to an enum in code: a component has a few properties, each one enum with exclusive cases and a default; the same names everywhere (type = what it is for, size, state = changes at run time, then slots such as icon, lead, trail); text and numbers are parameters, not variants; each variant row changes one property from the defaults and is named property.case. Everything is drawn by the same CSS as the screens on pages 2 and 3.
